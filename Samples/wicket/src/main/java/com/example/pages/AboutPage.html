About This Demo

This application is a minimal but realistic Task Manager built with Apache Wicket 10 running on an embedded Jetty 12 (Jakarta EE 10 / Servlet 6.0) server.

It is a deliberate port of the companion JSF / PrimeFaces demo — every feature maps 1-to-1: stat cards, Chart.js charts, paginated table, add / edit / delete tasks with AJAX partial updates.

The key Wicket philosophy: HTML templates are valid HTML files that designers can open directly in a browser — the wicket:id attributes are simply ignored by the browser but picked up by the Wicket runtime to wire components.

How Wicket Differs from JSF
Page-class + HTML template pairing
Every Wicket page is a plain Java class (WebPage subclass) paired with an HTML template of the same name. Components are added in Java (add(new Label("title", ...))) and bound to HTML via wicket:id. No annotations, no EL expressions in HTML.
AJAX via AjaxCheckBox / AjaxButton / AjaxLink
Wicket ships AJAX-aware versions of every standard form component. The onUpdate(AjaxRequestTarget) callback receives a target object; calling target.add(component) re-renders that component's markup in-place — exactly like PrimeFaces' update="componentId".
Charts via target.appendJavaScript()
Unlike PrimeFaces which generates Chart.js config from a Java model, Wicket takes a lower-level approach: chart data is computed in Java, serialised to a JSON literal string, and injected into a target.appendJavaScript() call that re-initialises the Chart.js instance after each AJAX update.
No hand-written AJAX boilerplate
Wicket generates all XMLHttpRequest wiring automatically. The developer only writes the onUpdate() / onSubmit() methods and declares which components to refresh — identical in spirit to JSF's partial-page rendering.
