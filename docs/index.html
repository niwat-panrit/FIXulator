FIXulator — User Guide

A FIX protocol simulator — initiator and acceptor — for testing and development.

Testing tool — not for production trading. FIXulator exists to exercise FIX integrations in development and QA. Do not connect it to a live venue and do not use it to send real orders. It is provided as is, without warranty of any kind, and its authors accept no liability for any loss arising from its use.

What FIXulator is

FIXulator drives FIX sessions from a browser. It works as an initiator, dialling out to a counterparty (an exchange simulator, a broker's UAT gateway, another test tool), or as an acceptor, listening on a port for a counterparty to connect to you. With it you can:

  • Configure and connect one or more FIX sessions, and watch their state live.
  • Send New Order Single, amend (cancel/replace), and cancel requests.
  • Compose and send an arbitrary raw FIX message.
  • Follow the full order lifecycle — New, PartFilled, Filled, Cancelled, and the rest.
  • Inspect every inbound and outbound message, decoded tag by tag.
  • Build reusable message templates with auto-generated and derived fields.

It does not match orders or simulate a market. It handles one side of the conversation; you supply the other end.

Installers bundle their own Java runtime, so you do not need a JDK. Download the file for your platform from the project's releases page.

Running from the JAR instead

If you build from source, the fat JAR needs a Java 17 runtime and nothing else:

cd src
mvn package
java -jar target/fix-simulator.jar        # port 8080
java -jar target/fix-simulator.jar 9090   # a different port

First run & sign in

  1. Launch FIXulator. It starts a local web server and prints the address.
  2. Open http://localhost:8080 in a browser.
  3. Sign in with the account created on first startup: username admin, password admin.

Change the default password immediately. The admin/admin account is created only when no users exist yet, purely so you can get in. Anyone who can reach the port can sign in with it. Go to User Management and set a real password before using FIXulator anywhere other than your own machine.

FIXulator remembers you for 30 days via a browser cookie, so you normally sign in once. Sign Out in the top-right clears that immediately.

The interface

Top bar

  • Session switcher — chooses which FIX session the pages act on. Orders, Trades, and FIX Activity all follow this selection, and it is remembered per user between restarts.
  • Connect / Listen — starts the selected session. The button follows what the session is doing: Connect or Listen when it is idle, Stop Connecting or Stop Listening (amber) while it is dialling out or waiting for a counterparty, and Disconnect (red) once a counterparty is logged on. So the button both shows the state and offers the opposite action.
  • Seq Mgmt — inspect and reset sequence numbers for the session.

Dashboard

Counters for active connections, total orders, filled trades, and messages in the last hour; a table of every configured session with its type, status, and TX/RX counts; and the most recent messages on the active session. It refreshes on its own.

FIX connections

Admin → FIX Connections. Add, edit, connect, disconnect, and delete sessions. Settings persist across restarts, as do sequence numbers.

FieldMeaning
Connection typeInitiator dials out; Acceptor listens.

Begin stringTransport version. Same as the FIX version for 4.x; FIXT.1.1 for 5.0 and later.
SenderCompIDYour identifier — tag 49 on outbound messages.
TargetCompIDThe counterparty's identifier — tag 56.

Reset on logonReset sequence numbers to 1 each time the session logs on.

A session sitting in CREATED with connection refused in the logs simply means nothing is listening at the other end yet. Start your counterparty, and FIXulator will retry on its own.

Acceptor sessions

An acceptor waits for the counterparty to connect to you. Choose Acceptor as the connection type and set the port to listen on; the host field is not used, since an acceptor binds all interfaces.

  • The port is bound as soon as the session starts, but the session stays inactive until you press Listen — exactly as an initiator does not dial until you tell it to. A counterparty that connects beforehand is refused. While it is listening the button reads Stop Listening, which releases it again.
  • Point your counterparty at this machine's address and that port, with its TargetCompID matching your SenderCompID and vice versa.
  • Two acceptor sessions cannot share a port. Give each its own. If the port is already in use, saving the session tells you so and keeps the session anyway: free the port and press Listen to retry, or edit the session onto a different port, which releases the old one. A session whose port is taken at startup is skipped and the reason written to the system log, so the app still runs.

Deleting a session archives its QuickFIX/J files rather than destroying them — they are renamed with a .deleted.<timestamp> suffix.

Orders

Monitoring → Orders. The order blotter for the active session, with every order you have sent and its live status.

Sending a new order

  1. Select the session in the top bar and connect it.
  2. Click New Order.
  3. Fill in symbol, side, quantity, price, order type, and time in force. ClOrdID is generated for you.
  4. Send. The order appears in the blotter and the message in FIX Activity.

If a template is available for the session, its choices populate the side, order type, and time-in-force dropdowns, and any extra fields it defines appear under Additional Fields. Hovering the action buttons shows which template applied.

Amending and cancelling

Amend opens a form pre-filled from the order, with a new ClOrdID generated and the original shown read-only; it sends an Order Cancel/Replace Request (35=G). Cancel sends an Order Cancel Request (35=F) immediately for that row.

Filtering

Filter by ClOrdID, symbol, side, order type, time in force, and status (New, PartFilled, Filled, DoneForDay, Cancelled, Stopped, Rejected, Suspended, Expired, PendCxl, PendReplace, PendingNew). Filters apply as you change them.

Trades

Monitoring → Trades. Execution reports that represent actual fills — partial fills, fills, and trades — rather than every acknowledgement. Filter by ExecID, ClOrdID, execution type, symbol, and side; 20 rows per page, refreshing automatically.

FIX Activity

Monitoring → FIX Activity. Every message in and out on the active session, newest first, plus application events.

  • Filters — direction (all, sent, received) and a hide heartbeats toggle. Your choices survive moving between pages.
  • Detail — click a row to see every tag with its name and decoded value, alongside the raw message.
  • Create Template from FIX Message — turns the selected message into a new template and opens it for editing. The quickest way to build one.

Compose a raw message

Available from Orders, Trades, and FIX Activity via Compose Message, which slides out from the side.

  1. Paste or type a raw FIX message. SOH-delimited and pipe-delimited (tag=value|tag=value) are both accepted.
  2. Parse checks it locally and shows a field-by-field breakdown with tag names and decoded values — nothing is sent.
  3. Send transmits it on the active session.

Session-level tags — 8, 9, 10, 34, 35, 49, 52, 56 — are owned by the FIX engine. If you supply them they are ignored, and correct values are substituted.

Message templates

Admin → FIX Message Templates. A template is a reusable message definition: fixed values, fields you fill in at send time, values generated automatically, and values derived from other fields.

Create one from scratch with New Template, or paste a raw message into Create Template from FIX Message and adjust the field types afterwards.

Scope decides visibility: a global template is offered on every session, a session template only on the one it belongs to.

Field types

TypeWhat it doesUse it for
LiteralA fixed value, sent as-is.Constants such as a fixed account.
User inputShows a text box on the order form.Symbol, quantity, price.
PlaceholderGenerated at send time.ClOrdID, TransactTime, SendingTime, UUID, the session's sender and target.
DerivedLooks the resolved value of another tag up in a mapping table. SecurityID from Symbol, via a symbol-to-ISIN mapping.
EnumerationRenders a dropdown.Side, order type, time in force.

Enumeration options are written KEY:LABEL — the key goes on the wire, the label appears in the UI. 1:Buy sends 1 and displays Buy. A plain value with no colon is used for both.

Declaration order does not matter for derived fields. Everything else is resolved first, then derived fields are resolved against those results — so a field may derive from one defined after it.

Dynamic values

Admin → Dynamic Values. Named tokens you can drop inside a template field's value using $(name) syntax — so a field can be part fixed text, part substitution, rather than wholly one or the other.

  • Built-in tokens such as $(order_id) and $(timestamp) are generated by the engine each time a message is sent. They cannot be edited or removed.
  • Custom tokens you define here substitute a fixed string wherever the token appears. Useful for a value repeated across many templates — change it once here and every template follows.

The page lists each token with its description and an example of how to write it.

Value mappings

Admin → Value Mappings. Named lookup tables of key → value, used by derived template fields. The shipped example maps symbols to ISINs, so a template can fill SecurityID automatically from whatever Symbol you typed.

Users & roles

Admin → User Management. Each user has a username (fixed once created), display name, password, email, roles, active flag, a maximum number of concurrent sessions (0 means unlimited), and a timezone.

Roles

RoleCan do
TesterOrders, trades, FIX activity, templates, dynamic values, value mappings, compose and send messages.
AdminEverything a Tester can, plus FIX connections, user management, and system logs.

Deactivating a user (clearing active) blocks sign-in without deleting anything.

Timezone

Every timestamp shown to a user — dashboard, FIX Activity, order send times, trade times — is rendered in that user's timezone. It defaults to UTC. Two people can watch the same session in their own local time.

System logs

Admin → System Logs. A live tail of the application log, with wrap and regex filtering, and a Download Log button for attaching to a bug report. This is the first place to look when a session will not connect.

Where your data lives

An installed FIXulator keeps everything it writes in your user profile, never inside the application folder:

PlatformLocation
Windows%LOCALAPPDATA%\FIXulator
macOS~/Library/Application Support/FIXulator
Linux$XDG_DATA_HOME/fixulator, otherwise ~/.local/share/fixulator

Inside it, data/ holds users, templates, dynamic values, value mappings, saved orders and trades; logs/ holds the log files; and fix-gateway.cfg holds session configuration.

To put that somewhere else — a server volume, a shared drive — set either:

-Dfixulator.home=/srv/fixulator     # JVM flag
FIXULATOR_HOME=/srv/fixulator       # environment variable

Running from a source checkout instead uses data/ and logs/ beside the working directory.

Backing up or moving a setup: copy the whole home directory. It is all plain text — YAML and logs — so it diffs and version-controls cleanly.

Troubleshooting

SymptomWhat it usually means
Connection refused repeating in the log Nothing is listening at the configured host and port. Start the counterparty; FIXulator retries automatically.
The app will not start, or the browser cannot reach it Another process holds port 8080. Start it on a different port: java -jar fix-simulator.jar 9090.
Logon is rejected by the counterparty SenderCompID / TargetCompID are swapped or misspelled, the begin string does not match what they expect, or sequence numbers are out of step. Try reset on logon, or reset sequence numbers from Seq Mgmt.
Orders and messages are missing The session switcher is on a different session. Pages only show the active one.
Everyone has forgotten their password Stop FIXulator, delete users.yaml from the data directory, and start again. The default admin/admin account is recreated, since no users exist. Nothing else is affected.
You want a completely clean slate Stop FIXulator and delete the home directory above. Everything is recreated on the next start.
